# Конвеєр моделей: від Meshy до гри

Одна команда перетворює сирий файл з Meshy (≈30 МБ, текстури PNG 2K/4K) на легкий GLB для гри (≈1,5 МБ):

```bash
npm run models warden
```

Без аргументів команда обробляє всі `art/meshy-source/<id>/<id>.glb`. Blender для цього не потрібен; він знадобиться лише тоді, коли модель перевищує бюджет трикутників.

## Як додати нову модель

1. **Згенерувати в Meshy** за рецептом з [пілоту Вартового](meshy-pilot.md#налаштування-meshy): Image to 3D (Meshy 7.1, Multi-view front+back, Resolution Standard, Texture 2K, A-Pose) → Remesh (Fixed, Triangle, ціль за бюджетом з `art/prompts/manifest.json`) → Rig → анімації → Download: glb, Skeleton template Mixamo, Animation All Added, Single file.
   - Персонажам з ригом потрібні **шість кліпів**: idle (пресет «Idle 1», бо «Idle» падає), Walking і Running (додаються з ригом), Attack, Hit Reaction, Dead. Магам додатково кліп із «Cast» або «Spell» у назві.
   - Зброю та пропи завантажувати без ригу й анімацій.
2. **Покласти сирий файл** у `art/meshy-source/<id>/<id>.glb`, де `<id>` береться з маніфесту. Ця папка не потрапляє в git, бо файли важать по 30 МБ.
3. **Запустити** `npm run models <id>`. Скрипт запише `assets/models/<id>/<id>.glb` і надрукує рядок таблиці (трикутники, текстури, кліпи, розмір до і після) та попередження:
   - `over the … budget`: трикутників більше за бюджет. Скрипт не спрощує меш; треба повторити Remesh у Meshy з меншою ціллю або зменшити модель у Blender.
   - `missing clips`: бракує кліпу з маніфесту. Варто довантажити анімацію в Meshy.
   - `matches no game clip name`: Meshy дав кліп з незнайомою назвою. Треба або перейменувати його в Meshy, або додати шаблон у `CLIP_PATTERNS` у `tools/optimize-models.mjs`.
4. **Перевірити**:
   - `npx vitest run tests/models`: файл читається, у персонажа з ригом є шість кліпів, текстури не більші за ліміт, трикутники вкладаються в бюджет, кістки з `attachTo` існують у скелеті власника, усі моделі разом важать до 60 МБ.
   - Подивитися модель в оглядачі: `npm run dev`, далі `http://localhost:5173/vidvazhni/dev/models.html?model=<id>`. Оглядач показує модель на клаптику дошки з тим самим світлом і нахилом камери, що в грі, і по черзі програє кліпи. Параметри:
     - `&view=close`: камера зблизька спереду;
     - `&compare=1`: сирий файл Meshy поруч з оптимізованим, щоб помітити втрати якості;
     - `&clip=attack`: програвати лише цей кліп;
     - `&hand=right`: жовтий брусок на кістці руки (перевіряє прикріплення);
     - `&weapon=<id>`: прикріпити модель зброї;
     - `&env=1`: додати карту оточення (див. «Відкриті питання»).
5. **Закомітити** лише `assets/models/<id>/<id>.glb`. Проміжні `<id>-1k.glb` з Blender більше не потрібні.

## Що робить скрипт

`tools/optimize-models.mjs` працює на glTF-Transform 4.5, meshoptimizer і sharp.

| Крок | Що відбувається |
|---|---|
| Кліпи | Назви нормалізуються: `Idle_02` → `idle`, `Walking` → `walk`, `Running` → `run`, `Attack` → `attack`, `Hit_Reaction` → `hit`, `Dead` → `death`, `Cast…`/`Spell…` → `cast`. Другий кліп того самого типу отримує назву `attack2`. |
| Root motion | У всіх кліпах, крім `walk` і `run`, кістка `mixamorig:Hips` тримає X/Z першого ключа. Вертикаль лишається, тож присідання й падіння на місці, але `hit` більше не зсуває героя на 0,8 м убік, а `attack` не робить випаду на 0,34 м. |
| Анімації | `resample` прибирає зайві ключі (у Вартового було 30 fps, лишилось 14 тис. ключів на 6 кліпів). |
| Меш | `dedup`, `prune`, `weld`, далі `meshopt` (reorder + quantize + `EXT_meshopt_compression`). Позиції та нормалі квантуються до 16 біт, UV до 16 біт, ваги до 8 біт. |
| Текстури | Ліміт 1024 px для героїв, монстрів і босів, 512 px для зброї та пропів. Формат WebP (якість 85, нормалі 90). Альфа-канал прибирається, якщо його ніхто не читає. Одноколірна текстура замінюється множником матеріалу. |
| Метадані | У `scene.extras.vidvazhni` записуються `id`, `kind`, `clips` і `attachTo` з маніфесту. GLTFLoader кладе їх у `scene.userData`, і `attachWeapon` бере звідти кістки. |

### Чому WebP, а не KTX2

- **WebP** читають і Safari на iPad (з iOS 14), і Chrome на Android; three.js підтримує його через `EXT_texture_webp` без додаткових декодерів. Скрипту вистачає `sharp` з npm без зовнішніх програм. Текстури Вартового стиснулися з 25 МБ PNG до 0,77 МБ.
- **KTX2/Basis** зменшив би відеопамʼять: WebP на GPU розпаковується в RGBA, тобто ≈5,3 МБ на текстуру 1024² з mip-рівнями, ≈16 МБ на унікальну модель героя (копії однієї моделі ділять текстури). Але KTX2 потребує `toktx` (KTX-Software) поза npm, транскодер Basis у WASM у збірці та перевірки на обох планшетах; файл при цьому був би більшим, ніж із WebP. Повернутися до KTX2 варто, якщо Android-планшет упреться у відеопамʼять, коли на полі буде багато різних моделей.

## Розміри

| Модель | Трикутники | Текстури | Кліпи | Сирий файл | Для гри |
|---|---|---|---|---|---|
| `warden` | 12 426 | 3 × 1024² WebP (color, normal, metal-rough) | idle, walk, run, attack, hit, death | 28,11 МБ (29,5 млн байт) | **1,48 МБ** |

Склад `warden.glb`: текстури 0,77 МБ (color 0,25 + normal 0,36 + metal-rough 0,16), меш, скін і шість кліпів разом ≈0,7 МБ. Проміжний `warden-1k.glb` з Blender важив 7,1 МБ.

**Оцінка для всього складу** (за маніфестом, з розмірами як у Вартового): 9 героїв × 1,5 + 11 монстрів × 1,2 + 2 боси × 2 + 9 одиниць зброї × 0,3 + 13 пропів × 0,4 ≈ **38 МБ**. Це в межах 60 МБ, але на текстури підлоги, звуки й код лишається ≈20 МБ. Найпростіший резерв: зменшити normal і metal-rough до 512 px (≈−0,35 МБ на персонажа, разом ≈−7 МБ). Різниця під кутом камери гри майже непомітна, а колір лишиться 1024. Таблицю оновлюйте за виводом `npm run models`.

## Завантаження в грі (`src/render/models.ts`)

```ts
import { loadModel, attachWeapon } from './render/models';

const warden = await loadModel('warden');      // клон: свій скелет і AnimationMixer, спільні геометрія й текстури
scene.add(warden.scene);                        // ступні на y = 0, обличчя в +Z
warden.play('walk');                            // crossFade 0,2 с за замовчуванням
warden.play('attack');                          // один раз, далі сам повертається в idle
warden.play('death');                           // один раз, тримає останній кадр
warden.update(dt);                              // щокадру, поки грає кліп
await attachWeapon(warden, 'warden-shield');    // кістки з manifest attachTo.bones
```

- GLB підключаються через `import.meta.glob(..., { query: '?url' })`: Vite кладе їх у `dist/assets` з хешем, і service worker PWA кешує їх для гри без інтернету. Перевірено збіркою: `warden-<hash>.glb` потрапляє в precache.
- У `attachTo.bones` маніфесту записані імена з GLB (`mixamorig:LeftHand`). GLTFLoader прибирає з імен `:`, тож у сцені кістка зветься `mixamorigLeftHand`; `findBone` приймає обидва варіанти.
- Положення зброї в долоні доведеться підбирати для кожної моделі окремо: `attachWeapon(model, id, { position, rotation, scale })`.

## Відкриті питання

- **Метал темний без карти оточення.** Дошка має лише hemisphere + directional світло, а броня Meshy металева (metallic до 1), тож вона виглядає майже чорною. З `RoomEnvironment` через PMREM (`&env=1` в оглядачі) Вартовий виглядає як у Blender: `pipeline/04-without-and-with-env-map.jpg`. Це питання до `render/board.ts`.
- **Модель на дошці.** `board.ts` поки не дає додати обʼєкт у сцену й рендерить лише на вимогу, а мікшеру потрібен цикл кадрів, поки грає кліп. Інтеграцію в дошку має зробити сесія рендеру.
- **Масштаб.** Вартовий має зріст 1,70 м, а гекс 2 одиниці від кута до кута; масштаб героя на дошці ще не обрано (`&scale=` в оглядачі).
- `modelFile` у маніфесті вказує на `assets/models/<id>.glb`, а конвеєр пише `assets/models/<id>/<id>.glb`.
