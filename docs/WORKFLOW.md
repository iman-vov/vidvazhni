# Як працюють паралельні сесії

Кілька сесій Claude працюють в одній папці `C:\Braves` одночасно. Щоб не заважати одна одній:

1. **Кожна сесія торкається лише своїх файлів** (перелік — у її завданні). Чужі файли тільки читає.
2. **Спільні контракти** — `src/rules/content.ts`, `state.ts`, `variants.ts`, `hex.ts`, `rng.ts`, `geometry.ts` (сигнатури), `ai/index.ts` (сигнатура), `engine.ts` (сигнатури). Змінювати їх можна лише **додаванням** (нове поле, новий варіант union), без перейменувань і видалень. Кожну таку зміну назвати у фінальному звіті.
3. **Коміти — лише своїх шляхів:** `git add <свої шляхи>` і `git commit`, ніколи `git add -A` чи `git commit -a`. Гілку не перемикати. Не пушити.
4. Повідомлення коміту закінчується рядком `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
5. Перед завершенням: `npx tsc --noEmit` і `npx vitest run` мають проходити; якщо падає чужий тест — не виправляти, а згадати у звіті.
6. Дизайн: `docs/design/osnova.md` (основа, нормативна) і `docs/design/fork.md` (обрані форк-механіки).
